This project was built with AI assistance under explicit, mechanically enforced guardrails. This
document answers the four disclosure questions and is updated with every feature.

## How the guardrails work

Prompts are suggestions; hooks and permissions are enforcement. Every rule below is enforced by
Claude Code itself, not by asking the model nicely.

| Rule | Enforced by |
|------|-------------|
| `test-author` writes only `tests/`; `implementer` only `src/`; `doc-writer` only docs; `reviewer` nothing | `PreToolUse` hooks in each agent's frontmatter (`.claude/hooks/path-guard.sh`), read-only tool list for the reviewer |
| The implementer cannot finish while the build or any test is red | `Stop` hook in the agent frontmatter runs the quality gate (`.claude/hooks/gate.sh`) |
| Nothing is committed unless build + tests pass; nothing lands on `main` unless the full gate passes | `PreToolUse` hook on `git commit` (`--fast` on branches, `--full` on `main`) |
| Tests cannot be changed during implementation | Write lanes above, plus a git audit after each implementation (`git diff --quiet -- tests/`) that also catches shell writes hooks cannot see |
| New or upgraded dependencies need a human | `ask` permissions on `dotnet add/package/tool`, `PreToolUse` hook on `Directory.Packages.props` |
| No force-push, every push needs a human, no network tools | `deny`/`ask` permission rules in `.claude/settings.json` |
| Humans decide the specification | The human approves `docs/SPEC.md`, the public contract, and every feature's test list before code is written |

`scripts/guardrail-selftest.sh` proves the hook scripts behave as described (12 checks). The lanes were
also tested live with the real agents:

| Live probe | Result |
|------------|--------|
| `implementer` asked to create a file in `tests/` | Denied: "agent 'implementer' may only write to: src/" — no file created |
| `test-author` asked to create a file in `src/` | Denied: "agent 'test-author' may only write to: tests/" — no file created |
